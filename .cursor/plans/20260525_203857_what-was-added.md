Created a project hook that ties GitHub PR creation to Linear issue updates, with a confirmation step before any Linear write.

## What was added

**`.cursor/hooks/pr-linear-sync.cjs`** — handles three events:

| Event | Trigger | Behavior |
|---|---|---|
| `postToolUse` | `gh pr create` (Shell) or `create_pull_request` (GitHub MCP) targeting `main`/`master` | Writes pending state, injects agent instructions to find and confirm the Linear issue |
| `beforeMCPExecution` | Linear `save_issue` while sync is pending | Returns `permission: "ask"` so you approve/reject the update in Cursor |
| `afterMCPExecution` | Successful `save_issue` | Clears pending state |

**`.cursor/hooks.json`** — registers the hook on those events.

**`.gitignore`** — ignores `.cursor/hooks/state/` (runtime pending sync file).

## Flow when you open a PR

1. Agent runs `gh pr create --base main` (or GitHub MCP `create_pull_request`).
2. Hook detects it, extracts PR URL + branch, and builds search hints:
   - `ZAW-123` in branch/commits
   - Slice IDs (`F-01`, `S-04`) and change IDs (`database-schema-and-rls`) from branch + `roadmap.md`
3. Agent gets injected instructions to follow `.cursor/skills/linear-mcp/SKILL.md`:
   - Search Linear for the related issue
   - **Ask you to confirm** the correct issue before updating
   - After confirmation: link PR, set status to **In Review**, add test-plan comment
4. When the agent calls Linear `save_issue`, Cursor shows an approval prompt — reject if it picked the wrong issue.

## Notes

- Restart Cursor (or reload hooks) if the hook doesn’t appear in **Settings → Hooks**.
- Works for `gh pr create` without `--base` (assumes default branch is `main`/`master`).
- PRs to other bases are ignored.
- Linear MCP auth must be connected (`user-Linear` server).

If you want, we can extend this to also handle `git push` + auto-created PRs, or map slice IDs to known ZAW issue numbers from your roadmap table.
